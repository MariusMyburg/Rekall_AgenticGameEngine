#

Getting started

AGE uses a repeatable loop: author world facts, inspect them, run the real runtime, and improve what the evidence reveals.

Project

A portable folder with rekall.project.json, scenes, assets, module source, and build receipts.

Scene

A named world document containing entities, hierarchy, tags, components, and properties.

Component

Inspectable data. Rekall.* types activate generic systems; Game.* types hold your game's state.

Module

User- or agent-authored C# that consumes input/events, queries entities, mutates the world, and emits observations.

Create, open, or use an example

  1. File → Create Project… asks for project name, location, and initial scene, then creates a new folder.
  2. File → Open Project… displays a folder browser. After opening, World is selected by default.
  3. Examples opens a writable copy of a shipped example; originals remain untouched.
  4. Choose a scene, inspect it in World, use Simulate for an editor run, and Play for the production Player.
First habit: after every meaningful change, select the entity and confirm its hierarchy, components, and values. A picture is useful; inspectable authored state is the truth.

First-launch language model setup

Studio checks its language-model configuration on first launch so the English-to-game workflow can be ready before you begin authoring. The wizard also reopens after an incomplete setup, an unreadable or newer settings record, or a completed provider configuration that is no longer usable.

This check never prevents you from opening a project or editing it manually. Choose Set Up Later to continue without a working authoring model. Studio then shows the compact AI setup incomplete · Configure recovery banner in World and Author. At any time, open Settings → Language Model Setup… to change provider, model, endpoint, or credentials.

Ollama recovery

  • Ollama is not installed: use Open Ollama download page, complete the installer yourself, then choose Retry. Studio does not silently download or run an installer.
  • Ollama is installed but stopped: choose Start Ollama. Studio launches the installed local service and checks readiness again.
  • Ollama has no models: choose Download qwen3.8:27b and keep the wizard open while bounded download progress is shown. You may cancel and retry.
  • Custom GGUF on a clean installation: first complete the executable/API steps above, choose Local GGUF, browse to a valid .gguf file, import it, then verify that the resulting model is tool-capable.

API keys and credential sources

Kimi and OpenAI accept three credential sources. Session only means a key entered explicitly in the current Studio session and cleared when Studio closes. An environment variable—KIMI_API_KEY or OPENAI_API_KEY—is read from the process environment. Remembered securely on this PC stores a Windows-protected credential for the current Windows user.

Remembered keys are encrypted using Windows data protection and are not stored in projects or normal settings files. The UI reports only the source label, never the key value. To revoke a stored credential, select Kimi or OpenAI in the wizard and choose Remove remembered key. This also clears the provider's session copy and reruns readiness checks. Environment variables must be removed from the Windows environment separately.

Finishing and revisiting setup

Finish becomes available only after the selected provider is reachable and the selected model is compatible. Studio saves only non-secret selection facts such as provider, endpoint, and model. A healthy completed setup is restored on later launches without showing the wizard; the Settings command always allows you to reopen it.

Build your first playable game

This recipe works for 2D or 3D because it describes facts and proof, not a hard-coded genre mode.

  1. Create a project with a Main scene.
  2. Prompt for the goal, semantic controls, world objects, hierarchy, camera, feedback, and visual direction.
  3. Ask for generic components, an attached Game.* component, and an authored C# module.
  4. Require representative deterministic input and a strict state-change assertion.
  5. Inspect hierarchy and every key entity in World. Test with Simulate, then Play.
  6. Package, run, capture, audit, and relocate the output before calling it delivered.
Create a complete 3D playable game called “Signal Run”.
Goal: reach three beacons before time expires.
Controls: expose semantic Move, Look, and Activate actions.
World: player, camera, terrain, beacons, timer, and clear UI feedback.
Use generic Rekall components plus Game.* state and an authored C# module.
Verify input changes a transform or Game.* property, then run the gauntlet.
Scenery is not gameplay. A build, screenshot, component existence check, or clean soak does not prove behavior is attached. Representative input must cause a strict executable state change.

Build the same slice manually

  1. Use Add Entity to create Player, Main Camera, Ground, and three Beacon entities. Rename immediately and parent decorative pieces beneath their owner.
  2. On Player add Rekall.Transform3D, a visible primitive or mesh, a matching collider, Rekall.Rigidbody3D, and Rekall.InputActionMap. Define a native JSON action named Move; do not put JSON inside a quoted string.
  3. On Main Camera add Rekall.Transform3D and Rekall.Camera3D. Position it via the transform; unrotated forward is +Z. Mark only the intended camera active.
  4. Give Ground a transform, visible renderer, and collider without a rigid body so it is static. Give beacons a tag such as beacon, visible geometry, and Rekall.Trigger.
  5. In Code choose New Entity Component, enter a module/component/system name, then Create, build & attach while Player is selected. Implement movement and beacon handling in that source.
  6. Save and Build. In Inspector confirm the generated Game.* component is attached to Player. Simulate and inspect; then Play in the production Player.

Exact component properties are schema-driven and shown inline by Inspector. Use reset/unset to return to schema defaults; use Advanced JSON only for genuinely structured values such as action arrays.

#

Author with an LLM

The LLM is an author using engine tools. Its durable output is ordinary project data, C# source, diagnostics, and playable evidence.

Providers

Studio supports Ollama (default local model qwen3.8:27b), local GGUF import through Ollama, Kimi with an API key, OpenAI with an API key, and Codex managed authentication. Only controls relevant to the selected provider appear. GGUF import requires a tool-capable model.

A strong request

  • State player-visible goal and completion/failure conditions.
  • Name semantic actions, not only raw keys.
  • Specify 2D/3D, camera behavior, hierarchy, visual direction, and performance constraints.
  • Require Game.* state and an authored module for custom rules.
  • Require deterministic runtime inspection after the latest mutation.
  • Ask for rekall.workflow.agent_authoring_gauntlet for closed-loop delivery.

Operations and receipts

Status may cover model work, tool calls, scene edits, C# writes, module builds, validation, runtime inspection, package, launch, capture, and audit. A module receipt connects source identity to compiled output. Missing or stale receipts should rebuild in the normal run flow; repair compiler errors and rerun the same proof rather than bypassing trust or weakening assertions.

Projects, scenes, and entities

Entities have stable IDs, names, optional parentage and tags, visibility, and components. Systems interpret those facts.

Hierarchy matters

Use parent/child structure for a rover and wheels, character and equipment, or canvas and controls. Child transforms compose beneath the parent, and the tree communicates ownership to humans and agents.

IdentityBest use
IDStable exact references.
NameHuman navigation and clear singleton queries.
TagGroups such as enemies, pickups, and terrain.
ComponentCapability/state queries.

Queries and mutation

Modules should use FindEntity, EntitiesNamed, EntitiesWithTag, EntitiesWithComponent, and combined queries. Mutate through ReplaceEntity, RemoveEntity, UpdateEntity, filtered update helpers, WithTag, WithVisible, and typed component helpers. Helpers return a replacement world: retain it and continue from that lineage.

Add/Replace is literal: one component per exact type; replacing supplies the complete component. Unknown Rekall.* names are reserved, while trusted project modules can define other namespaces such as Game.*.

Editing: booleans and choices commit immediately; text/vectors commit on Enter or focus loss; JSON uses Ctrl+Enter. Escape restores. Colors are #RRGGBB or #RRGGBBAA; numeric values must be finite and within declared ranges.

#

C# gameplay modules

Use modules for rules: movement, scoring, AI, inventory, spawning, quests, and event response.

  1. In Code, open or scaffold a runtime-system source.
  2. Edit in Studio or open its generated solution/project in Visual Studio or VS Code.
  3. Save and Build. Scaffold-and-attach can create the component, build, and attach it to the selected entity.
  4. Run deterministic inspection; use the generated IDE configuration for F5 debugging of the Vulkan Player.

SDK essentials

  • Use context.DeltaTime or input delta seconds for all realtime behavior.
  • Read/write game state through typed component helpers.
  • Consume InputActionValue, IsInputActionDown, and WasInputActionPressed; define the matching InputActionMap.
  • Use Forward3D, Right3D, Up3D, and Offset3D for camera-relative math.
  • Use EmitObservation and EmitSceneObservation for actionable diagnostics.

Events

Implemented facts include entity.begin, entity.tick, timer.elapsed, pointer enter/leave/hit/down/up/click, collision begin/stay/end, and trigger enter/stay/exit. Use EmitEvent and EmitBoundEvents for game-specific facts.

Minimal compilable runtime-system shape

The scaffold command creates this structure for you. This complete example registers a schema-backed component and moves every entity carrying it. One module directory compiles as one assembly, so keep type names unique.

using Rekall.Age.Modules;
using Rekall.Age.Runtime.Abstractions;

namespace Game.Modules.Motion;

[RekallAgeModule("game.motion", "Motion")]
[RekallAgeRequiresCapability("world")]
public sealed class MotionModule : RekallAgeModule
{
    public override void Configure(RekallAgeModuleBuilder builder)
    {
        builder.RegisterComponent<Motion>();
        builder.RegisterRuntimeSystem<MotionSystem>();
    }
}

[RekallAgeComponent("Motion")]
public sealed class Motion : RekallAgeComponent
{
    [RekallAgeProperty] public bool Enabled { get; init; } = true;
    [RekallAgeProperty(Minimum = 0)]
    public double UnitsPerSecond { get; init; } = 2;
}

public sealed class MotionSystem : IRekallAgeRuntimeModuleSystem
{
    const string Type = "Game.Modules.Motion.Motion";
    public string Id => nameof(MotionSystem);
    public int Priority => 0;

    public ValueTask<RekallAgeRuntimeWorld> UpdateAsync(
        RekallAgeRuntimeWorld world,
        RekallAgeRuntimeModuleFrameContext context)
    {
        var dt = context.DeltaTime.TotalSeconds;
        var next = world.Entities.Select(entity =>
        {
            var motion = entity.Components.FirstOrDefault(c => c.Type == Type);
            if (motion is null) return entity;
            var speed = RekallAgeRuntimeModuleSdk.ComponentNumber(
                entity, Type, "unitsPerSecond", 2);
            return entity with { Transform = entity.Transform with {
                Position3D = entity.Transform.Position3D with {
                    X = entity.Transform.Position3D.X + speed * dt
                }
            }};
        }).ToArray();
        return ValueTask.FromResult(world with { Entities = next });
    }
}

For semantic controls, read the action from the frame/context using the SDK helpers exposed by the current scaffold. Input helpers consume mappings; they do not create them. Run module schemas project and SDK inspection whenever signatures or component properties may have evolved.

#

Assets, 3D modeling, and materials

Use project-relative asset references so projects and packages remain portable.

Mesh round trip

  1. Select an entity with ModelAssetReference and choose Edit Linked Model. Editable linked sources must be Mesh assets.
  2. Edit mesh operations and stable elements in Modeling; preview, apply, or cancel revision-safe operations.
  3. Publish a new model or Rebuild the linked model. Editing alone does not sync back.
  4. Place/sync it into the scene, optionally under a parent, then verify the original entity in World and Player.

Procedural geometry supports opening/evaluating graphs, typed parameters, node dragging, and links; it is not yet a complete graph-construction UI. Material graphs have typed revision-safe parameters but no material-to-pixel preview—inspect the result in runtime. UV/Attributes is currently inspection-only. Animation editing covers existing AnimationMixer layers and authored initial state.

#

Rendering

World builds the actual runtime world, UI layout, projection, frame, and assets, then presents via Vulkan. Play uses the production Vulkan Player.

Color and quality

Camera clear color should agree between Inspector, World, and Player. The renderer must convert linear values to an sRGB swapchain exactly once. If they differ, check active camera, alpha, format, and conversion rather than compensating authored color. Jagged output usually points to physical drawable size, render scale, antialiasing, or quality profile.

Vulkan unavailable

  • Update the GPU driver and run backend/device probes.
  • Read the first Studio log exception to distinguish loader, adapter, and device failure.
  • Edit-mode rendering can remain available without executing untrusted project modules.
  • Property edits should not detach/recreate a top-level native window; recovery should keep authoring usable without white flashes.

Performance

Separate simulation and presentation cost. Check repeated resource rebuilds, swapchain recreation, synchronous readback, repeated exceptions, oversized geometry/XR targets, and physics substeps. Movement remains delta-time based at every frame rate.

Physics and simulation

Physics advances with a controlled clock and bounded stepping. Render cadence can vary without changing gameplay speed.

Match 2D bodies/colliders to Transform2D and 3D to Transform3D. Use materials for friction/restitution, filters for interaction groups, triggers for overlap facts, and joints for constraints. Game meaning—damage, pickups, suspension—belongs in modules consuming generic events.

Very slow Simulate

Pause and Step to isolate one tick. Inspect for builds inside the frame loop, Vulkan surface recreation, capture/readback, dense mesh colliders, unbounded substeps, or an exception logged every frame.

#

Audio, UI, and animation

Place one intended AudioListener, use emitters for clips/spatial settings, buses for routing, and procedural clips for generated audio. Verify device output and attenuation in Player.

A UiCanvas defines reference coordinates; elements, panels, labels, images, and buttons share geometry, anchors, offsets, pivots, visuals, text, interaction, navigation order, and layout. Parent screen UI beneath its canvas.

Clips carry tracks/events; players play; mixers blend; state graphs transition. Skeletal animator/pose/rig/attachment and morph components handle imported rigs and shapes. All timing uses elapsed seconds, never rendered-frame count.

#

Multiplayer

MultiplayerSession, NetworkIdentity, and NetworkTransform are generic replication contracts. They preserve role, authority, ownership, replicate flags, prediction mode, and priority.

Use SDK session/entity/ownership queries and IsNetworkOwner/IsReplicated. Clients should use the supplied snapshot interpolator, reconciler, applier, and delta builder. Runtime commands cover host, status, connect/disconnect, input, tick, snapshot, and delta over named-pipe or WebSocket transports.

Virtual reality and OpenXR

XrRig, XrPoseSource, and XrController describe XR state. Playable VR uses the visible Windows Player, preserving desktop keyboard/mouse input alongside OpenXR poses/actions.

  • Start the OpenXR runtime and wake the headset.
  • Probe/bootstrap and require loader/runtime, XR_KHR_vulkan_enable2, HMD, and two stereo views.
  • Launch Player with --graphics --backend vulkan --vr; tune eye width/height if runtime resolution is too expensive.
  • The standalone scene submitter is headless diagnostics, not normal playable input.
dotnet run --project src/Rekall.Age.Cli -- render openxr bootstrap-session
Rekall.Age.Player.Windows.exe <project> <scene> --graphics --backend vulkan --vr

Build and ship

Studio packages Windows and Headless targets and exposes web publish/audit workflows.

  1. Save scenes/code, build modules, validate, and rerun gameplay proof.
  2. Package to the selected target and run the returned launch path.
  3. Capture and audit the artifact.
  4. Relocate/extract it elsewhere and run again to expose absolute references.
Package inspection path: pass the output directory, rekall.package.json, or ZIP—not the executable launch path.

CLI and agent tools

CLI and MCP share the engine command registry. Start with rekall.context.engine_status, discover component schemas, and inspect before mutating.

World

rekall.project.*, rekall.scene.*, and rekall.entity.*.

Modules

Schema search, SDK inspect/install, source list/read/write/scaffold, build, and trust.

Runtime/render

Workflow/network

Verify, gauntlet, package, run, capture, audit, relocate; host/connect/input/tick/snapshot/delta.

Use bounded operations, preserve unrelated authored state, follow diagnostics/next actions, and keep game rules in modules/examples unless a primitive is genuinely engine-general.

CLI invocation pattern and working examples

From the repository, substitute the installed CLI executable for the dotnet run prefix in a distribution. Quote paths and JSON as required by your shell.

# General form
dotnet run --project src/Rekall.Age.Cli -- <domain> <verb> [arguments]

# Discover schemas and inspect project module trust
dotnet run --project src/Rekall.Age.Cli -- module schemas
dotnet run --project src/Rekall.Age.Cli -- module schemas project "C:\Games\SignalRun"
dotnet run --project src/Rekall.Age.Cli -- module trust "C:\Games\SignalRun"

# Create project/scene/entity (capabilities/tags are comma-separated)
dotnet run --project src/Rekall.Age.Cli -- project create "C:\Games\SignalRun" "Signal Run" "world,rendering3d"
dotnet run --project src/Rekall.Age.Cli -- scene create "C:\Games\SignalRun" Main "world,rendering3d"
dotnet run --project src/Rekall.Age.Cli -- entity create "C:\Games\SignalRun" Main Player "player,controllable"

# Scaffold, build, validate, and inspect deterministic frames
dotnet run --project src/Rekall.Age.Cli -- module scaffold-runtime-system "C:\Games\SignalRun" game.motion "Motion" MotionModule Motion MotionSystem
dotnet run --project src/Rekall.Age.Cli -- build modules "C:\Games\SignalRun"
dotnet run --project src/Rekall.Age.Cli -- validation scene "C:\Games\SignalRun" Main
dotnet run --project src/Rekall.Age.Cli -- runtime inspect "C:\Games\SignalRun" Main 3

# Closed-loop acceptance and narrower delivery commands
dotnet run --project src/Rekall.Age.Cli -- game gauntlet "C:\Games\SignalRun" "Signal Run"

Troubleshooting

Capture the project, scene, entity, mode, provider/model, command, timestamp, and first exception. The first error is usually more useful than repeated frame-loop fallout.

SymptomRepair direction
Selection clears itselfPreserve selection by stable ID across hierarchy refresh; clear only if the entity disappeared.
Property has no effectCheck schema, validation, commit gesture, and component instance.
White flash on edit/SimulateKeep the native Vulkan child attached; avoid top-level window/swapchain churn.
Camera color differsCheck active camera, alpha, and one linear-to-sRGB conversion.
Jagged outputCheck physical drawable size, render scale, AA, and quality profile.
Simulate is very slowMeasure rebuilds, recreation, readback, repeated errors, and physics work.
Vulkan unavailableProbe driver/loader/adapter/device and read the first Studio exception.
Custom shader throwsRepair shader compilation/bindings/fallback in the generic material contract.
Receipt missingRebuild automatically or Build Modules; repair compiler output and rerun proof.
AI setup is blockedOpen First-launch language model setup and follow the provider-specific readiness action.
LLM controls feel unrelatedSelect the intended provider; only its auth/endpoint controls should show.
Agent says done; game inertCheck attached Game.*, action map, trusted receipt, and strict input assertion.

Diagnostic ladder

Engine status → engine doctor → project/scene validation and repair → SDK/trust/receipt/build → render visibility/performance/backend → deterministic runtime inspection → soak → recovery reports → package/web audit.

#

Advanced architecture

AGE separates authored facts from generic systems that interpret them, allowing arbitrary games without privileging a genre or controller.

  • Core: project/world documents, commands, persistence, compatibility.
  • Systems: rendering, input, events, physics, audio, animation, UI, networking, XR, scheduling.
  • Authoring: Studio, CLI/MCP, schemas, diagnostics, previews, workflows.
  • Game: Game.* state, C# modules, scenes, assets, and examples.

Extension rule

First ask whether an authored module can implement behavior using existing queries, mutations, events, semantic input, vector helpers, observations, and runtime render projections. If yes, improve those primitives or their discoverability. Add a core primitive only when unrelated games need the same low-level inspectable contract.

Emit structured observations for missing/inconsistent content. Cache resources by stable identity/revision. Keep clocks explicit and input frames serializable. Examples are acceptance consumers: fix a generic contract first, then update the example.
